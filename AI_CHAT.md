# Чат с ИИ: тестовый harness

Раздел `/ai` — экспериментальная вкладка в боковом меню («Чат с ИИ»). Это не
просто чат, а небольшой harness: подключение к локальной модели, тип раздумий,
параметры генерации, вложения и RAG по выбранной папке.

Блок помечен как тестовый: история чатов и расход токенов хранятся **в базе за
аккаунтом**, в браузере остаются только настройки подключения (адрес, ключ,
модель) и параметры генерации.

Подходит любой OpenAI-совместимый сервер: Unsloth, llama.cpp, vLLM, LM Studio,
Ollama в режиме `/v1` — нужны `/v1/chat/completions` и (по желанию) `/v1/models`.

## Как подключить

1. Запустите локальный сервер, например Unsloth (по умолчанию он слушает
   `http://127.0.0.1:8888/v1`).
2. Откройте `/ai`, в блоке «Подключение» заполните:
   * **Base URL** — `http://127.0.0.1:8888/v1`;
   * **ApiKey** — значение вида `sk-unsloth-…` (если сервер работает без ключа,
     поле можно оставить пустым — заголовок `Authorization` тогда не уходит);
   * **Модель** — имя из списка сервера или вручную.
3. Кнопка с обновлением рядом с моделью запрашивает `/v1/models`, показывает
   количество моделей и подставляет первую, если поле пустое.

Те же значения можно задать переменными окружения — они используются, когда
поля в интерфейсе пустые:

```bash
AI_BASE_URL=http://127.0.0.1:8888/v1
AI_API_KEY=sk-unsloth-...
AI_MODEL=unsloth/gemma-3-4b-it
```

Важно: запрос к модели делает **сервер Nova CRM**, а не браузер. Поэтому
`127.0.0.1` означает машину, где запущен CRM. Если CRM в контейнере, адрес
локальной модели нужно указывать с точки зрения контейнера
(`host.docker.internal`, IP хоста и т. п.).

## Тип раздумий

У моделей с режимом размышлений (Qwen3, DeepSeek-R1, gpt-oss, o-series) разные
серверы принимают разные параметры, поэтому в блоке «Раздумья модели» есть
несколько режимов:

| Режим | Что уходит в запрос |
| --- | --- |
| По умолчанию | ничего — решает сервер и шаблон модели |
| Без раздумий | `reasoning_effort: "none"` (+ `chat_template_kwargs.enable_thinking: false`) |
| Коротко / Средне / Глубоко | `reasoning_effort: "low" / "medium" / "high"` |
| Свой бюджет | `thinking_budget: N` и `reasoning_effort: "high"` |

Галочка «Дублировать в `chat_template_kwargs.enable_thinking`» нужна
Qwen3/Unsloth; некоторым сборкам это поле мешает — снимите её, если сервер
отвечает `400`. Если сервер вообще не понимает параметры раздумий, выберите
«По умолчанию».

Ответы серверов, которые отдают `delta.reasoning_content` (или
`delta.reasoning`), показываются отдельным сворачиваемым блоком
«Размышления · N симв.».

## Параметры генерации

В блоке «Генерация»: `system prompt`, `temperature`, `top_p`, `max_tokens`,
`seed` и число фрагментов RAG. Пустое поле = параметр не отправляется вовсе —
это важно для строгих сборок, которые отвергают незнакомые поля.

Всё это хранится в браузере (`localStorage`) и сбрасывается кнопкой
«Сбросить всё». Лимиты токенов этими параметрами не обходятся — их задаёт роль
(см. «Ограничения по ролям»).

## RAG окружение (папка)

1. В блоке «RAG окружение» нажмите «Загрузить папку» и укажите каталог с
   документацией или кодом.
2. Браузер локально читает файлы и извлекает из них текст:
   * текст, код, CSV/JSON/HTML — как есть (до 200 тыс. символов на файл);
   * `docx`, `xlsx`, `pptx`, `odt`, `ods`, `odp`, `epub` — распаковка ZIP и
     вычитка XML;
   * `pdf` — текстовые операторы из потоков (FlateDecode), если текст в файле
     извлекается;
   * `rtf` — снятие управляющих последовательностей;
   * картинки и бинарные файлы в индекс не попадают (только прикладываются к
     вопросу).
3. Текст режется на фрагменты по ~900 символов и **загружается в базу частями**
   (до 4 МБ текста за запрос) в папку пользователя. Ограничений на число файлов,
   их размер (кроме 20 МБ на файл) и суммарный объём папки нет.
4. Индекс хранится в таблицах `ai_rag_folders`, `ai_rag_chunks`, `ai_rag_terms`
   за конкретным пользователем: перезагрузка страницы, перезапуск CRM и смена
   вкладки его не сбрасывают. Чужие папки недоступны — все запросы проверяют
   владельца.
5. На каждый вопрос сервер ищет лучшие фрагменты (BM25-подобный счёт по основам
   слов, поэтому «смета»/«сметы»/«сметой» находятся одинаково) и вставляет их в
   промпт отдельным системным сообщением. Сколько фрагментов брать — параметр
   «Фрагментов RAG» (0 — отключить).

### «Вся база» — без ограничения фрагментов

Галочка **«Вся база»** рядом с числом фрагментов отправляет модели **весь индекс
папки**, а не топ-N:

* сервер читает все фрагменты (`listRagChunks`), сортирует их: сначала самое
  релевантное вопросу, затем остальное в документном порядке;
* контекст собирается функцией `formatFullRagContext`: фрагменты одного файла
  идут под общим заголовком `Файл: …`, между файлами — разделитель;
* потолок задаёт только контекст модели — параметр «Контекст» в блоке «Токены»
  (`contextLimit`). Если он равен 0 («не следить»), действует техническая
  страховка `RAG_FULL_MAX_CHARS` = 2 млн символов на запрос;
* бюджет в символах считает `ragBudgetChars`: `(contextLimit − занято историей −
  резерв на ответ) × 2,4`. Резерв — `max_tokens` или 1024 токена;
* если весь индекс не влезает, обрезается **хвост** (наименее релевантное), а в
  ответе появляется пометка `📁 5/30` янтарного цвета с подсказкой, сколько
  фрагментов вошло и какой у модели контекст. Если влезло всё — `30/30` обычным
  цветом.

Пример: папка на 25 тыс. символов (30 фрагментов) при `contextLimit: 0` уходит
целиком (в промпт попадает 25 818 символов); при `contextLimit: 3000` — только
5 самых релевантных фрагментов и `truncated: true`.

Так что «полное RAG-окружение» возможно в пределах контекста модели: ограничение
на число фрагментов снимается полностью, а физический предел — окно модели.
6. Кнопка поиска рядом с полем «Проверить поиск по папке» показывает, что именно
   найдётся по запросу, — удобно проверять папку перед вопросами. Кнопка
   «Удалить» убирает папку и все её фрагменты из базы.

## Файлы и картинки в вопросе

Кнопка-скрепка принимает **любой тип файла до 20 МБ** (до 4 файлов на вопрос):

* **картинки** — уменьшаются до 1600 px по длинной стороне и уходят как
  `image_url` с data-URL (обычный снимок с телефона превращается в ~300 КБ), для
  vision-моделей;
* **текст, код, CSV/JSON/HTML** — вставляются в промпт текстом с именем файла;
* **docx / xlsx / pptx / pdf / rtf / odt / ods / odp / epub** — извлекается текст
  (как и для RAG), в промпт уходит он;
* **всё остальное** — уходят имя, тип и размер: модель хотя бы знает о файле;
  в интерфейсе такой файл помечен предупреждением.

Файлы читаются в браузере — содержимое не уходит на сервер в виде файла, в
запрос попадает уже текст (или картинка). Превью и удаление доступны до отправки.

## Токены, история и новый чат

* Счётчики ведутся **в базе за аккаунтом**, а не в браузере: они видны на вкладке
  `/ai`, в профиле (`/profile`) и в карточке сотрудника (`/team/<id>`).
* Под каждым ответом — `↑вход ↓выход` этого хода; в шапке чата — остаток по
  текущему чату; в блоке «Токены аккаунта» — расход за месяц, месячный лимит и
  остаток, а также сумма за всё время.
* Если сервер присылает `usage` в потоке (`stream_options.include_usage`), числа
  точные; иначе токены считаются оценкой по символам (кириллица ≈ 2,5 символа на
  токен) и так и помечаются.
* «История чатов» слева — все чаты аккаунта с датой и **остатком токенов в
  каждом**; чат открывается кликом, удаляется корзиной (расход аккаунта при этом
  сохраняется).
* Кнопка **«Новый чат»** создаёт новый чат: переписка и счётчик токенов
  начинаются с нуля, старые чаты остаются в истории. Настройки подключения,
  параметры и выбранная RAG-папка сохраняются.
* Лимиты проверяются и в интерфейсе, и на сервере: при исчерпании лимита чата
  или месячного лимита `/api/ai/chat` отвечает `403` с понятным текстом, а кнопка
  отправки блокируется.

## Ограничения по ролям

| Роль | Токенов на чат | В месяц | Шагов агента/оператора | RAG | Раздумья |
| --- | --- | --- | --- | --- | --- |
| Главный админ | без лимита | без лимита | без лимита | да | любые |
| Администратор | 1 млн | без лимита | до 500 | да | любые |
| Разработчик | 1 млн | 5 млн | до 500 | да | любые |
| Менеджер | 1 млн | 1,5 млн | до 500 | нет | без / коротко |
| Консультант | 1 млн | 500 тыс. | до 500 | нет | без / коротко |
| Сотрудник | 1 млн | 500 тыс. | до 500 | нет | без / коротко |

* У **главного администратора** нет ограничений ни по токенам (на чат и в месяц),
  ни по шагам агента/оператора; для всех остальных ролей (включая обычного
  **администратора**) действует лимит шагов до **500** и лимит токенов на чат.
* Количество чатов не ограничено ни для одной роли.
* Если роль не разрешает выбранный режим раздумий, сервер молча понижает его до
  «коротко» (в ответе приходит `reasoningDowngraded: true`), а RAG-запрос
  отклоняется с `403`.
* Месячный лимит может расширить **только администратор** — на карточке
  сотрудника (`/team/<id>` → «Лимит ИИ на этот месяц») или через
  `setAiQuotaAction`. Расширение действует до конца текущего месяца и не меняет
  роль; снять его можно кнопкой «Сбросить».
* После исчерпания месячного лимита помогает только продление администратором —
  новый чат его не обнуляет (обнуляется лишь счётчик чата).

## Подвкладки страницы и агент (Python)

Страница `/ai` разделена на подвкладки, состояние между ними не теряется:

| Вкладка | Кому видна | Что внутри |
| --- | --- | --- |
| «Чат с моделью» | всем ролям | привычный harness: файлы, RAG, раздумья, история |
| «Агент» | **только главный администратор** | Python-агент с инструментами |
| «Оператор» | **только главный администратор** | бот, который управляет рабочим столом: очередь заданий, шаги, файлы |
| «Лимиты и расход» | всем ролям | счётчик токенов и таблица правил по ролям |

### Агент

Агент — отдельный процесс на Python (`agent/agent.py`, только стандартная
библиотека), он не входит в сборку Next.js:

```bash
python3 agent/agent.py                     # слушает 127.0.0.1:8899
AGENT_PORT=9001 python3 agent/agent.py     # другой порт
AGENT_URL=http://host:9001 ...            # CRM ищет агента по этой переменной
```

Что умеет:

* **создавать файлы** — `create_file` (CSV, markdown, HTML, код). Файл
  сохраняется в `agent/workspace/` и приходит в браузер готовой ссылкой на
  скачивание (до 400 КБ);
* **открывать сайты** — `open_website` (только `http/https`);
* **включать видео** — `play_youtube`: открывает YouTube с автозапуском
  первого результата по запросу.

Пример: «Открой ютуб и включи видео про космос» → агент вызывает
`play_youtube`, браузер открывает вкладку, в диалоге остаётся карточка
«YouTube: космос» — если всплывающее окно заблокировано, по ней можно нажать.

**Вложения в чате агента.** Скрепка рядом с полем ввода принимает до 5 файлов
по 10 МБ: текст распознаётся в браузере (docx/xlsx/pdf/rtf/html — тем же
`src/lib/fileExtract.ts`, что и в обычном чате), и в `POST /api/ai/agent` уходит
уже `attachments: [{ name, note, text, image? }]`. Агент приклеивает этот текст к
последнему сообщению пользователя и отвечает по содержимому файла. Картинки
уходят как `image_url` (data-URL, до 3 штук): vision-модель видит сам снимок, а
текстовая — получает только пометку и не роняет запрос. Результат агент
возвращает файлом через `create_file` — карточка «скачать» появляется прямо в
ответе (до 400 КБ, `agent/workspace/`).

**Раздумья и генерация.** На вкладке «Агент» есть блок с теми же ручками, что в
«Чате с моделью»: режим раздумий (по умолчанию / без раздумий / коротко / средне
/ глубоко / свой бюджет), `temperature`, `top_p`, `max_tokens`, `seed` и галочка
`chat_template_kwargs.enable_thinking`. Блок открыт по умолчанию; настройки
хранятся в браузере (`crm.ai.agent.params.v1`), уходят в `params` и применяются
к каждому запросу к модели. Рядом — настройка шагов агента: для главного
администратора по умолчанию без лимита (и без потолка 500), для остальных ролей
(включая администратора) предел **500** шагов. Если сервер отдаёт
`reasoning_content`, размышления показываются в ответе раскрывающимся блоком.

Пример: «посчитай суммы из этого csv и пришли отчёт» + `expenses.csv` →
агент читает строки, вызывает `create_file` с `report.md`/`xlsx`, в диалоге
появляется ссылка на скачивание.

Как он устроен: CRM (`POST /api/ai/agent`) проверяет роль, добавляет контекст
(имя, роль, дата) и проксирует SSE-поток агента. Агент общается с тем же
OpenAI-совместимым сервером, что и чат: адрес, ключ и модель вводятся в
интерфейсе (и дублируются переменными `AGENT_BASE_URL`, `AGENT_API_KEY`,
`AGENT_MODEL`). Если сервер умеет function calling — используется он, если нет —
агент переходит на JSON-протокол (`{"tool": "...", "args": {...}}`), поэтому
работает и с простыми локальными сборками.

### Оператор рабочего стола

Вкладка «Оператор» — очередь заданий для бота `agent/desktop_operator.py`,
который запускается на компьютере пользователя: смотрит на экран, кликает,
печатает и собирает файлы. Бот забирает задания по токену (`x-agent-token`),
ключ модели остаётся у него — CRM получает только шаги и файлы.

Оформление — только средствами CRM (`Card`, `Button`, `Badge`, `EmptyState`,
токены `border-border`/`bg-card2`/`accent`), никаких внешних стилей. Внутри три
подвкладки:

| Подвкладка | Что внутри |
| --- | --- |
| «Пульт» | счётчики очереди и **два чата**: «Планировщик» и «Выполнение», ниже — ход запуска (текущий шаг, `action.json`, лента действий, файлы) |
| «Запуски» | история заданий с фильтрами по статусу; клик открывает запуск на «Пульте» |
| «Подключение» | подключения (адрес CRM) и их токены: список, создание, «Показать», «Отозвать»; проверка связи, установка зависимостей, сборка команды запуска: провайдер, модель, ключ API и флаги |

**Подключения и токены.** «Подключение» — это адрес CRM, с которым работает бот
(«Этот CRM», «Тестовый сервер», сервер заказчика). Они хранятся в базе под
пользователем (`agent_connections`), поэтому список одинаков на любом компьютере
и переживает перезапуск; у каждого — свой набор токенов
(`agent_connection_tokens`: по одному на машину). В списке токен виден маской
(`…abcdef`), полное значение выдаёт только кнопка **«Показать»** — и тогда токен
подставляется в команду запуска. **«Отозвать»** удаляет один токен, не трогая
остальные. Токенов нет в списке — значит бот не запустится: создайте токен,
скопируйте команду и запустите бота. Старый одиночный токен (`agent_tokens`)
переезжает в подключение «Основной CRM» при первом старте, поэтому работающие
боты не отваливаются. Маршруты — `/api/agent/connections` и `/api/agent/tokens`
(полное значение токена отдаёт `POST /api/agent/tokens/reveal`), доступ у
главного администратора.

**Два чата на «Пульте».** Слева — планировщик (`POST /api/agent/plan`): вы
пишете задачу словами, модель уточняет её и выдаёт пошаговый план с критерием
«Готово, когда…». История план-чатов хранится в базе
(`agent_conversations`, `kind = "plan"`), чаты переключаются, создаются заново и
удаляются. У каждого план-чата есть свой редактируемый **системный промпт**
(`systemPrompt`, по умолчанию подставляется пример из `src/lib/operatorPlan.ts`,
его можно менять или сбросить к примеру, изменения автосохраняются для выбранного
чата). Справа — чат с действиями: сюда план попадает кнопкой
**«Перенести в выполнение»** и уходит ботом в очередь (`POST /api/agent/tasks`).
Автозапуска нет: без нажатия кнопки (или «В очередь») бот ничего не делает.
Ключ модели для планировщика берётся из тех же настроек «Подключения» и в базу
не попадает. Для главного администратора лимит шагов можно отключить («Без лимита
шагов») либо задать любое значение; для остальных ролей, включая обычных админов,
действует потолок **500** шагов.

**Ручная проверка подключения бота.** В шапке «Оператора» есть кнопка
**«Проверить подключение бота»** (`GET /api/agent/bot/status`): проверка
срабатывает только по клику (без фонового heartbeat и постоянного индикатора) и
показывает, выходил ли бот на связь недавно (по `last_used_at` токенов и текущей
задаче `running`), каким токеном и сколько заданий в очереди. В подвкладке
«Подключение» дополнительно остаётся кнопка **«Проверить связь»**
(`GET /api/agent/bot/whoami` с `x-check-only: 1`) для проверки конкретного токена
без изменения даты его последней активности.

**Раздумья, генерация и проверка действий.** Блок «Раздумья и генерация» на
«Пульте» задаёт режим раздумий, бюджет, `temperature`, `top_p`, `max_tokens` и
`seed`. Планировщик получает их в `settings.params`, а бот — флагами команды
запуска (`--temperature`, `--reasoning`, …): поменяли настройки — нажмите
**«Скопировать команду с этими настройками»** в том же блоке и перезапустите бота. Там же переключатель **«Анализировать экран после каждого
действия»** (по умолчанию включён): после клика/ввода бот снимает скриншот,
спрашивает модель «получилось ли?» и присылает событие `result` — `✅` или `⚠️`
с пояснением, а вердикт попадает в историю шагов.

**Вложения.** В обоих чатах скрепка принимает до 5 файлов по 10 МБ. Текст
распознаётся в браузере; в планировщик он уходит вместе с вопросом, а бот
скачивает сами файлы заданий по `GET /api/agent/bot/attachment/<id>` и вставляет
прочитанный текст в первый шаг (`docx`/`xlsx` — из XML, картинки — как
изображения, до 3 штук: бот видит снимок). В ленте появляется «Прочитал
вложения задания».

**Защита от зацикливания.** Бот запоминает отпечаток действия (тип, координаты,
текст). Если одно и то же повторяется подряд, модель получает вспомогательный
промпт «ты застрял, экран не меняется» со списком других шагов (Esc, alt+tab,
прокрутка, открыть программу, finish); с третьего повтора действие не выполняется,
на пятом задание останавливается с понятной ошибкой. Успешная проверка экрана
сбрасывает счётчик, поэтому повторные клики «следующая страница» не блокируются.

**Курсор перед кликом.** На скриншоте рисуется красный крестик в текущей точке
курсора, а перед нажатием бот проверяет `pyautogui.position()`: если курсор не
встал куда вели (допуск 3 px) или точка вне экрана, клик отменяется с понятной
ошибкой в ленте — вместо открытия чужого приложения.

Счётчики и лента обновляются сами: очередь раз в 3,5 с, шаги открытого задания
— раз в 2,5 с, и только когда открыта подвкладка «Пульт».

* файлы (docx, xlsx, csv, md, html, svg, zip…) появляются карточками в чате и
  скачиваются из браузера (`/api/agent/file/<id>`);
* модель — локальная или облачная: `--provider local|openai|openrouter|groq|deepseek|together|mistral`;
* команду запуска собирает «Подключение»: провайдер, модель, **ключ API**, адрес CRM
  и флаги (`--once`, `--dry-run`, `--yes`, `--text-only`), остаётся скопировать её в терминал;
  ключ подставляется в команду флагом `--api-key` или строкой
  `export DEEPSEEK_API_KEY=…` и в CRM не сохраняется — без ключа облачный провайдер
  отвечает 401 «Модель отклонила ключ API»;
* зрение зависит от модели, а не от провайдера: у DeepSeek для экрана нужен
  `deepseek-flash` (`deepseek-chat` картинок не принимает), и он подставляется по
  умолчанию. Бот проверяет зрение при запуске, а флаг `--vision` отключает
  проверку, если модель точно vision;
* проверить токен можно там же кнопкой **«Проверить связь»** — она берёт токен, показанный в подключении, или вставленный вручную (`GET /api/agent/bot/whoami`)
  или из консоли: `python3 agent/desktop_operator.py --check --token crmop_…`. Маршрут
  принимает токен в `x-agent-token` и в `Authorization: Bearer`; в ответе — владелец и
  счётчики очереди, поэтому сразу видно, что дело не в токене, а в модели или адресе;
* инструкция — [`agent/OPERATOR.md`](agent/OPERATOR.md).

### Провайдеры моделей

Оба агента работают с любым OpenAI-совместимым API. На вкладке «Агент» есть
переключатель провайдера (локальная модель, OpenAI, OpenRouter, Groq, DeepSeek,
Together, Mistral или свой адрес): он подставляет Base URL и модель, ключ
хранится в браузере и уходит только в запросе.

**История чатов вкладки «Агент».** Диалоги на вкладке «Агент» также хранятся
в базе (`agent_conversations` / `agent_conversation_messages`, `kind = "agent"`):
можно переключаться между прошлыми чатами, создавать новые и удалять старые.
Свежесозданные агентом файлы остаются доступными для скачивания в текущем
сеансе, а в базу для экономии места сохраняются только имена, MIME-типы и
размеры вложений и созданных файлов — без байтов содержимого (при повторном
открытии чата из истории они показываются как метаданные с пометкой «файл не
сохранён»). Расход токенов агента в месячные лимиты не попадает (доступ у роли
без лимита), действия выполняются в браузере пользователя.

## Стенограмма

Кнопка со стрелкой вниз в шапке чата скачивает `.md` с перепиской, вложениями,
размышлениями, токенами и параметрами модели — удобно приложить к багу или
поделиться результатом.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/ai/chat` | прокси к `/chat/completions`: SSE `{"delta":"…"}`, `{"reasoning":"…"}`, `{"usage":{…}}`, `{"done":true,"ragHits":N,"chat":{…},"monthly":{…}}` |
| `GET` | `/api/ai/models?base=…` | список моделей сервера для кнопки проверки |
| `GET` | `/api/ai/usage` | расход аккаунта, лимиты роли, расширение месяца |
| `GET` | `/api/ai/chats` | история чатов с остатком токенов |
| `POST` | `/api/ai/chats` | новый чат (`{ title? }`) |
| `GET` | `/api/ai/chats/[id]` | сообщения чата |
| `DELETE` | `/api/ai/chats?id=N` | удалить чат вместе с сообщениями |
| `GET` | `/api/ai/rag` | папки RAG текущего пользователя |
| `POST` | `/api/ai/rag` | создать папку: `{ name }` |
| `DELETE` | `/api/ai/rag?id=N` | удалить папку со всеми фрагментами |
| `POST` | `/api/ai/rag/chunks` | догрузить файлы: `{ folderId, items: [{ path, chunks }] }` (до 4 МБ текста за запрос) |
| `POST` | `/api/ai/rag/search` | проверить поиск: `{ folderId, query, limit }` |
| — | `params.ragFull` | `true` — отдавать весь индекс папки (без ограничения фрагментов); в SSE `done` приходит `ragFull: { used, total, chars, truncated, budgetChars, contextLimit }` |
| `GET` | `/api/ai/agent` | жив ли Python-агент, его инструменты (только главный админ) |
| `POST` | `/api/ai/agent` | запуск агента: SSE `status` / `reasoning` / `text` / `action` / `error` / `done`; тело `{ messages, settings, params, maxSteps, attachments }` |
| `POST` | `/api/agent/plan` | чат-планировщик оператора: `{ messages, files, systemPrompt?, settings: { baseUrl, apiKey, model, params } }` → `{ reply, reasoning? }` |
| `GET` | `/api/agent/conversations?kind=plan\|agent` | список чатов планировщика или агента |
| `POST` | `/api/agent/conversations` | создать чат (`{ kind, title?, systemPrompt? }`) |
| `GET` / `PATCH` / `DELETE` | `/api/agent/conversations/[id]` | открыть сообщения/промпт, обновить название/промпт, удалить чат |
| `POST` | `/api/agent/conversations/[id]/messages` | сохранить сообщение и метаданные файлов (без байтов) |
| `GET` | `/api/agent/bot/status` | ручная проверка активности бота по кнопке (без изменения `last_used_at`) |
| `POST` | `/api/agent/tasks` | задание боту: `{ prompt, maxSteps, files: [{ name, mime, size, data }] }` (до 5 файлов по 10 МБ) |
| `GET` | `/api/agent/bot/[id]` | статус задания и `attachments` (токен агента) |
| `GET` | `/api/agent/bot/attachment/[id]` | скачать вложение задания (токен агента) |

Тело `POST /api/ai/chat`: `{ chatId, messages, params, attachments, ragFolderId, ragQuery }`.
`chatId` — чат из истории (если не передан, создаётся новый), `attachments` —
метаданные вложений для истории, `ragFolderId` — сохранённая папка: сервер сам
найдёт фрагменты по последнему вопросу (`ragQuery` — если нужен свой запрос).
Ответ модели, размышления и расход токенов записываются в базу сервером.

Все роуты требуют сессию (`401` без неё). Адрес и ключ передаются заголовками
`x-ai-base` и `x-ai-key`, модель — `x-ai-model`; в журналы и базу они не
попадают. Разрешены только `http(s)`-адреса, таймаут ответа — 5 минут, тело
запроса ограничено 48 МБ.

## Ограничения тестового режима

* Настройки подключения и параметры генерации живут в браузере (`localStorage`),
  история чатов, расход токенов и RAG-папки — в базе за аккаунтом.
* Вложения сохраняются в истории только метаданными (имя, тип, размер): после
  перезагрузки страницы в контекст уходит лишь текст переписки.
* Нет векторных эмбеддингов (поиск лексический).
