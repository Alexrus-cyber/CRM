# Чат с ИИ: тестовый harness

Раздел `/ai` — экспериментальная вкладка в боковом меню («Чат с ИИ»). Это не
просто чат, а небольшой harness: подключение к локальной модели, тип раздумий,
параметры генерации, вложения и RAG по выбранной папке.

Блок помечен как тестовый: история чатов и расход токенов хранятся **в базе за
аккаунтом**, в браузере остаются только настройки подключения (адрес, ключ,
модель) и параметры генерации.

Подходит любой OpenAI-совместимый сервер: Unsloth, llama.cpp, vLLM, LM Studio,
Ollama в режиме `/v1` — нужны `/v1/chat/completions` и (по желанию) `/v1/models`.

## Как подключить

1. Запустите локальный сервер, например Unsloth (по умолчанию он слушает
   `http://127.0.0.1:8888/v1`).
2. Откройте `/ai`, в блоке «Подключение» заполните:
   * **Base URL** — `http://127.0.0.1:8888/v1`;
   * **ApiKey** — значение вида `sk-unsloth-…` (если сервер работает без ключа,
     поле можно оставить пустым — заголовок `Authorization` тогда не уходит);
   * **Модель** — имя из списка сервера или вручную.
3. Кнопка с обновлением рядом с моделью запрашивает `/v1/models`, показывает
   количество моделей и подставляет первую, если поле пустое.

Те же значения можно задать переменными окружения — они используются, когда
поля в интерфейсе пустые:

```bash
AI_BASE_URL=http://127.0.0.1:8888/v1
AI_API_KEY=sk-unsloth-...
AI_MODEL=unsloth/gemma-3-4b-it
```

Важно: запрос к модели делает **сервер Nova CRM**, а не браузер. Поэтому
`127.0.0.1` означает машину, где запущен CRM. Если CRM в контейнере, адрес
локальной модели нужно указывать с точки зрения контейнера
(`host.docker.internal`, IP хоста и т. п.).

## Тип раздумий

У моделей с режимом размышлений (Qwen3, DeepSeek-R1, gpt-oss, o-series) разные
серверы принимают разные параметры, поэтому в блоке «Раздумья модели» есть
несколько режимов:

| Режим | Что уходит в запрос |
| --- | --- |
| По умолчанию | ничего — решает сервер и шаблон модели |
| Без раздумий | `reasoning_effort: "none"` (+ `chat_template_kwargs.enable_thinking: false`) |
| Коротко / Средне / Глубоко | `reasoning_effort: "low" / "medium" / "high"` |
| Свой бюджет | `thinking_budget: N` и `reasoning_effort: "high"` |

Галочка «Дублировать в `chat_template_kwargs.enable_thinking`» нужна
Qwen3/Unsloth; некоторым сборкам это поле мешает — снимите её, если сервер
отвечает `400`. Если сервер вообще не понимает параметры раздумий, выберите
«По умолчанию».

Ответы серверов, которые отдают `delta.reasoning_content` (или
`delta.reasoning`), показываются отдельным сворачиваемым блоком
«Размышления · N симв.».

## Параметры генерации

В блоке «Генерация»: `system prompt`, `temperature`, `top_p`, `max_tokens`,
`seed` и число фрагментов RAG. Пустое поле = параметр не отправляется вовсе —
это важно для строгих сборок, которые отвергают незнакомые поля.

Всё это хранится в браузере (`localStorage`) и сбрасывается кнопкой
«Сбросить всё». Лимиты токенов этими параметрами не обходятся — их задаёт роль
(см. «Ограничения по ролям»).

## RAG окружение (папка)

1. В блоке «RAG окружение» нажмите «Загрузить папку» и укажите каталог с
   документацией или кодом.
2. Браузер локально читает файлы и извлекает из них текст:
   * текст, код, CSV/JSON/HTML — как есть (до 200 тыс. символов на файл);
   * `docx`, `xlsx`, `pptx`, `odt`, `ods`, `odp`, `epub` — распаковка ZIP и
     вычитка XML;
   * `pdf` — текстовые операторы из потоков (FlateDecode), если текст в файле
     извлекается;
   * `rtf` — снятие управляющих последовательностей;
   * картинки и бинарные файлы в индекс не попадают (только прикладываются к
     вопросу).
3. Текст режется на фрагменты по ~900 символов и **загружается в базу частями**
   (до 4 МБ текста за запрос) в папку пользователя. Ограничений на число файлов,
   их размер (кроме 20 МБ на файл) и суммарный объём папки нет.
4. Индекс хранится в таблицах `ai_rag_folders`, `ai_rag_chunks`, `ai_rag_terms`
   за конкретным пользователем: перезагрузка страницы, перезапуск CRM и смена
   вкладки его не сбрасывают. Чужие папки недоступны — все запросы проверяют
   владельца.
5. На каждый вопрос сервер ищет лучшие фрагменты (BM25-подобный счёт по основам
   слов, поэтому «смета»/«сметы»/«сметой» находятся одинаково) и вставляет их в
   промпт отдельным системным сообщением. Сколько фрагментов брать — параметр
   «Фрагментов RAG» (0 — отключить).
6. Кнопка поиска рядом с полем «Проверить поиск по папке» показывает, что именно
   найдётся по запросу, — удобно проверять папку перед вопросами. Кнопка
   «Удалить» убирает папку и все её фрагменты из базы.

## Файлы и картинки в вопросе

Кнопка-скрепка принимает **любой тип файла до 20 МБ** (до 4 файлов на вопрос):

* **картинки** — уменьшаются до 1600 px по длинной стороне и уходят как
  `image_url` с data-URL (обычный снимок с телефона превращается в ~300 КБ), для
  vision-моделей;
* **текст, код, CSV/JSON/HTML** — вставляются в промпт текстом с именем файла;
* **docx / xlsx / pptx / pdf / rtf / odt / ods / odp / epub** — извлекается текст
  (как и для RAG), в промпт уходит он;
* **всё остальное** — уходят имя, тип и размер: модель хотя бы знает о файле;
  в интерфейсе такой файл помечен предупреждением.

Файлы читаются в браузере — содержимое не уходит на сервер в виде файла, в
запрос попадает уже текст (или картинка). Превью и удаление доступны до отправки.

## Токены, история и новый чат

* Счётчики ведутся **в базе за аккаунтом**, а не в браузере: они видны на вкладке
  `/ai`, в профиле (`/profile`) и в карточке сотрудника (`/team/<id>`).
* Под каждым ответом — `↑вход ↓выход` этого хода; в шапке чата — остаток по
  текущему чату; в блоке «Токены аккаунта» — расход за месяц, месячный лимит и
  остаток, а также сумма за всё время.
* Если сервер присылает `usage` в потоке (`stream_options.include_usage`), числа
  точные; иначе токены считаются оценкой по символам (кириллица ≈ 2,5 символа на
  токен) и так и помечаются.
* «История чатов» слева — все чаты аккаунта с датой и **остатком токенов в
  каждом**; чат открывается кликом, удаляется корзиной (расход аккаунта при этом
  сохраняется).
* Кнопка **«Новый чат»** создаёт новый чат: переписка и счётчик токенов
  начинаются с нуля, старые чаты остаются в истории. Настройки подключения,
  параметры и выбранная RAG-папка сохраняются.
* Лимиты проверяются и в интерфейсе, и на сервере: при исчерпании лимита чата
  или месячного лимита `/api/ai/chat` отвечает `403` с понятным текстом, а кнопка
  отправки блокируется.

## Ограничения по ролям

| Роль | Токенов на чат | В месяц | RAG | Раздумья |
| --- | --- | --- | --- | --- |
| Главный админ | 1 млн | без лимита | да | любые |
| Администратор | 1 млн | без лимита | да | любые |
| Разработчик | 1 млн | 5 млн | да | любые |
| Менеджер | 1 млн | 1,5 млн | нет | без / коротко |
| Консультант | 1 млн | 500 тыс. | нет | без / коротко |
| Сотрудник | 1 млн | 500 тыс. | нет | без / коротко |

* Количество чатов не ограничено ни для одной роли.
* Если роль не разрешает выбранный режим раздумий, сервер молча понижает его до
  «коротко» (в ответе приходит `reasoningDowngraded: true`), а RAG-запрос
  отклоняется с `403`.
* Месячный лимит может расширить **только администратор** — на карточке
  сотрудника (`/team/<id>` → «Лимит ИИ на этот месяц») или через
  `setAiQuotaAction`. Расширение действует до конца текущего месяца и не меняет
  роль; снять его можно кнопкой «Сбросить».
* После исчерпания месячного лимита помогает только продление администратором —
  новый чат его не обнуляет (обнуляется лишь счётчик чата).

## Стенограмма

Кнопка со стрелкой вниз в шапке чата скачивает `.md` с перепиской, вложениями,
размышлениями, токенами и параметрами модели — удобно приложить к багу или
поделиться результатом.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/ai/chat` | прокси к `/chat/completions`: SSE `{"delta":"…"}`, `{"reasoning":"…"}`, `{"usage":{…}}`, `{"done":true,"ragHits":N,"chat":{…},"monthly":{…}}` |
| `GET` | `/api/ai/models?base=…` | список моделей сервера для кнопки проверки |
| `GET` | `/api/ai/usage` | расход аккаунта, лимиты роли, расширение месяца |
| `GET` | `/api/ai/chats` | история чатов с остатком токенов |
| `POST` | `/api/ai/chats` | новый чат (`{ title? }`) |
| `GET` | `/api/ai/chats/[id]` | сообщения чата |
| `DELETE` | `/api/ai/chats?id=N` | удалить чат вместе с сообщениями |
| `GET` | `/api/ai/rag` | папки RAG текущего пользователя |
| `POST` | `/api/ai/rag` | создать папку: `{ name }` |
| `DELETE` | `/api/ai/rag?id=N` | удалить папку со всеми фрагментами |
| `POST` | `/api/ai/rag/chunks` | догрузить файлы: `{ folderId, items: [{ path, chunks }] }` (до 4 МБ текста за запрос) |
| `POST` | `/api/ai/rag/search` | проверить поиск: `{ folderId, query, limit }` |

Тело `POST /api/ai/chat`: `{ chatId, messages, params, attachments, ragFolderId, ragQuery }`.
`chatId` — чат из истории (если не передан, создаётся новый), `attachments` —
метаданные вложений для истории, `ragFolderId` — сохранённая папка: сервер сам
найдёт фрагменты по последнему вопросу (`ragQuery` — если нужен свой запрос).
Ответ модели, размышления и расход токенов записываются в базу сервером.

Все роуты требуют сессию (`401` без неё). Адрес и ключ передаются заголовками
`x-ai-base` и `x-ai-key`, модель — `x-ai-model`; в журналы и базу они не
попадают. Разрешены только `http(s)`-адреса, таймаут ответа — 5 минут, тело
запроса ограничено 48 МБ.

## Ограничения тестового режима

* Настройки подключения и параметры генерации живут в браузере (`localStorage`),
  история чатов, расход токенов и RAG-папки — в базе за аккаунтом.
* Вложения сохраняются в истории только метаданными (имя, тип, размер): после
  перезагрузки страницы в контекст уходит лишь текст переписки.
* Нет векторных эмбеддингов (поиск лексический).
