# CRM Agents — настольный ИИ-harness и запускатор агентов

Полноценное настольное приложение на Python в стиле раздела «Чат с ИИ» сайта Nova CRM.
Подключается к базе данных CRM через учётку сайта (URL CRM + email + пароль + 2FA),
при этом **Агент с инструментами** (`agent/agent.py`) и **Оператор рабочего стола**
(`agent/desktop_operator.py`) работают локально прямо внутри `.exe`.

Основные вкладки окна (доступны согласно правам учётки CRM):

1. **Чат с моделью** — диалоги из БД CRM, RAG-папки (поиск и загрузка файлов/папок ПК),
   вложения (включая Word/Excel/PPTX/ODT и скриншоты Ctrl+V), режимы раздумий,
   потоковый вывод и прямое обращение к локальным моделям ПК (`127.0.0.1` / LAN).
2. **Агент** — встроенный локальный `agent.py` с рабочей папкой на ПК, чатами БД,
   подтверждениями (Approval), Sandbox-превью/экспортом на ПК, стенограммами (Summary),
   RAG, GitHub-контекстом, подвкладкой **Субагенты и Надсмотрщик** (дерево, мгновенное
   вкл/выкл Надсмотрщика, прямой чат с субагентом) и **Тестировщиком (QA)**.
3. **Оператор** — встроенный `desktop_operator.py` с автоподстановкой токена CRM,
   Пультом (лента скриншотов/действий, подсказки, Советчик Агента), Планировщиком,
   историей запусков и управлением подключениями/токенами.
4. **Лимиты и расход** — квоты по ролям, расход токенов (включая панель Агента/Оператора
   для `super_admin`) и диагностика среды/логов `.exe`.

Собирается в **единое настольное приложение (`CRM Agents.exe`)**: внутри Python,
веб-UI (`launcher/ui/`), движок окна (`pywebview` + fallback на Edge/Chrome `--app=`),
сами агенты и их зависимости (`Pillow`, `pyautogui`, `pyperclip`, `pywebview`).
На машине пользователя ничего ставить не нужно — ни Python, ни pip, ни пакеты.

## Быстрый старт (из исходников)

```bash
python launcher/cli.py           # или: python -m launcher (новое окно CRM Harness)
python -m launcher --headless    # только локальный сервер + URL в консоли
python -m launcher --classic-tk  # классический Tkinter-интерфейс
python -m launcher --list        # что умеет запускать
python -m launcher --self-test   # 96 проверок без экрана и сети
```

Требуется Python 3.10+. Для окна предпочтительно `pywebview` (WebView2 на Windows);
при его отсутствии приложение автоматически открывает отдельное app-окно Edge/Chrome
без адресной строки либо системный браузер.

## Сборка exe

```bash
pip install -r launcher/requirements.txt
python launcher/build_exe.py
```

Готовый файл — `dist/CRM Agents/CRM Agents.exe` (папка). Сборка делается на той ОС,
для которой нужен exe (PyInstaller не кросс-компилирует). Флаги:

| Флаг | Что делает |
| --- | --- |
| *(по умолчанию)* | папка `dist/CRM Agents/` — **рекомендуемый режим** |
| `--onefile` | один файл `dist/CRM Agents.exe` |
| `--tmpdir ПАПКА` | куда однофайловой сборке распаковывать runtime (по умолчанию `%TEMP%`) |
| `--no-install` | не ставить зависимости (они уже есть) |
| `--wheels` | скачать колёса в `launcher/wheels/` — для офлайн-доустановки |

Что попадает в сборку:

* `launcher/*.py` — локальный сервер (`harness_server.py`), разбор файлов (`file_extract.py`), окно (`desktop_window.py`), классический GUI и CLI;
* `launcher/ui/` → внутрь exe в папку `ui/` (интерфейс в стиле Nova CRM);
* `agent/desktop_operator.py`, `agent/agent.py`, `agent/overseer.py`, `agent/fileforge.py` и модули инструментов → внутрь exe
  в папку `agents/`;
* пакеты из `launcher/requirements.txt` — замораживаются PyInstaller'ом;
* `launcher/wheels/`, если папка есть, — запасной офлайн-источник пакетов.

## Как приложение запускает агентов без Python на машине

В exe нет отдельного интерпретатора, поэтому приложение запускает **самого себя**
в режиме агента:

```
CRM Agents.exe --run-agent agents/desktop_operator.py --watch --token … --model …
```

`--run-agent` выполняет встроенный скрипт в текущем процессе (`runpy`) — так
работают встроенные агенты. Для «своего агента» нужен Python на машине: путь к
интерпретатору берётся из `sys.executable`, поэтому в exe это работает только для
встроенных скриптов (приложение честно предупредит об этом).

### Почему по умолчанию папка, а не один файл

Однофайловая сборка при каждом старте распаковывает runtime во временную папку.
Когда приложение запускает агента, оно стартует **самого себя** — и наивный
повторный запуск пытается распаковаться заново. Если Windows не даёт писать в
`TEMP` (политика, антивирус, переполнение, длинный путь), bootloader показывает

> Error. Could not create temporary directory!

и агент завершается с кодом `-1` (в журнале — `4294967295`).

Что делает приложение, чтобы этого не было:

* дочернему процессу передаются `_PYI_APPLICATION_HOME_DIR` и
  `_PYI_PARENT_PROCESS_LEVEL` — bootloader понимает, что это **своя же** программа,
  и переиспользует уже распакованный runtime, ничего не распаковывая;
* `TEMP`/`TMP`/`TMPDIR` дочернего процесса указывают на свою writable-папку
  `…/CRM Agents/tmp` (создаётся и проверяется на запись при запуске);
* если `_MEIPASS` не существует или папка недоступна, приложение показывает
  понятное объяснение вместо кода `-1`;
* код выхода расшифровывается: `-1`/`4294967295` → подсказка про `--onedir`,
  `--tmpdir`, `TEMP` и антивирус; `-1073741819` → access violation и т. п.

Если всё равно хочется один файл: `python launcher/build_exe.py --onefile
--tmpdir D:\crm-temp` — тогда runtime распаковывается в указанную папку, а не в
системный `TEMP`.

## Если при запуске ошибка «Could not create temporary directory!»

1. Проверьте кнопкой «Проверить окружение»: строки `временная папка агента`,
   `запись во временную папку`, `_MEIPASS существует`.
2. Соберите папкой: `python launcher/build_exe.py` (режим по умолчанию) — у
   onedir распаковки нет вовсе.
3. Либо укажите свою папку: `python launcher/build_exe.py --onefile --tmpdir D:\crm-temp`.
4. Убедитесь, что exe запускается не из ZIP-архива, а из обычной папки, и что
   антивирус не блокирует запись в `%TEMP%`.

Код `4294967295` в журнале — это `-1` в беззнаковой записи, то есть ошибка
bootloader'а, а не агента: скрипт агента даже не начал выполняться.

## Агенты

| Агент | Что делает | Нужно |
| --- | --- | --- |
| **Оператор рабочего стола** (`desktop_operator.py`) | смотрит на экран, кликает, печатает, собирает файлы; режимы «слушать очередь CRM», «одно задание», «разовое задание» | модель с vision, экран, токен CRM |
| **Агент с инструментами** (`agent.py`) | чат-агент для страницы `/ai`: файлы, сайты, видео; поднимает локальный сервер | модель |
| **Свой агент** | любой ваш `.py` с аргументами | Python на машине |

Поля агентов хранятся отдельно друг от друга: переключение не затирает введённое.

## Настройки и где они лежат

| Что | Windows | Linux/macOS |
| --- | --- | --- |
| Настройки | `%APPDATA%\CRM Agents\launcher.json` | `~/.config/crm-agents/launcher.json` |
| Рабочая папка агентов | `%APPDATA%\CRM Agents\workspace` | `~/.config/crm-agents/workspace` |
| Свой каталог агентов | `agents.json` рядом с настройками | там же |

`CRM_LAUNCHER_CONFIG=/path/to/settings.json` переносит всё в указанное место —
удобно для «портативной» сборки на флешке.

Ключ API на диск не пишется, пока не отмечена галочка «Сохранять ключ API».
В журнале и в строке запуска секреты заменяются на `•••`.

## Свои агенты

1. Положите скрипт рядом с приложением (или укажите его путь в поле «Python-файл»).
2. Либо опишите агента в `agents.json` рядом с настройками:

```json
{
  "agents": [
    {
      "id": "my-bot",
      "title": "Мой бот",
      "subtitle": "делает что-то полезное",
      "description": "Описание для карточки",
      "script": "my_agent.py",
      "requires": ["model"],
      "fields": [
        {"key": "target", "label": "Куда смотреть", "kind": "text", "default": "C:\\docs"},
        {"key": "loud", "label": "Подробный лог", "kind": "bool", "default": true}
      ]
    }
  ]
}
```

Скрипт получит аргументы `--target … --loud` и переменные `AGENT_BASE_URL`,
`AGENT_MODEL`, `AGENT_API_KEY`. Файл `my_agent.py` кладётся в папку `agents/`
внутри сборки либо указывается абсолютным путём в `script`.

## Зависимости и офлайн

- В собранном exe зависимости уже внутри: проверка «Проверить окружение» покажет
  «есть» для Pillow / pyautogui / pyperclip.
- Если exe собрали без них, приложение предложит доставить пакеты из
  `wheels/` рядом с exe (`pip install --no-index --find-links`), без интернета.
  Колёса готовятся флагом `python launcher/build_exe.py --wheels`.
- Для запуска из исходников: `pip install -r launcher/requirements.txt`.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl+A` / `Ctrl+C` / `Ctrl+X` / `Ctrl+V` | выделить, копировать, вырезать, вставить в полях и журнале (включая русскую раскладку и сборки PyInstaller; на macOS также `Cmd+A/C/X/V`) |
| `Ctrl+Enter` | запустить выбранного агента |
| `Ctrl+.` | остановить |

Горячие клавиши редактирования привязаны напрямую к виджетам в `launcher/gui.py`
(`_bind_edit_shortcuts`), чтобы буфер обмена и выделение работали в переносимых
сборках `dist/` без установки Python и без зависимости от системных привязок Tk
на компьютере получателя.

## Что проверяет self-test

`python -m launcher --self-test` — 58 проверок:

* каталог агентов и провайдеров;
* сборка аргументов оператора (режимы, параметры генерации, флаги проверки и
  антизацикливания) и переменных `agent.py`;
* разбор аргументов своего агента с кавычками;
* секреты не попадают в описание команды и в файл настроек без разрешения;
* сохранение/загрузка настроек;
* проверка зависимостей и поиск скриптов в сборке;
* запуск процесса и чтение вывода, вырезание ANSI;
* `--run-agent` выполняет скрипт;
* кодировка вывода: `child_env` выставляет `PYTHONIOENCODING=utf-8` и
  `PYTHONUTF8=1`, `ensure_std_streams` переводит `cp1251`-потоки в UTF-8 с
  `errors="replace"`, и `--run-agent` не падает на кириллице и символах вроде
  `→` при `cp1251` в окружении;
* `launcher.spec` исполняется с заглушками PyInstaller: точка входа, агенты в
  `datas`, скрытые импорты, оконный режим exe;
* среда запуска агента: своя writable-временная папка, переиспользование
  распакованного runtime в onefile и отказ от него во второй попытке;
* расшифровка кодов выхода (`-1`/`4294967295` и др.);
* интерфейс на заглушке tkinter: форма, смена агента, `Ctrl+A/C/V` в полях и
  журнале (включая русскую раскладку), подстановка провайдера, запуск агента и
  запись в журнал, сохранение настроек при выходе.
