# CRM Agents — настольный запускатор ИИ-агентов

Одно окно: слева список агентов, справа настройки модели и агента, снизу журнал.
Пользователь выбирает агента, вводит адрес API и модель, нажимает «Запустить» —
приложение поднимает агента отдельным процессом и показывает его вывод.

Собирается в **один exe**: внутри Python, tkinter, сами агенты и их зависимости
(Pillow, pyautogui, pyperclip). На машине пользователя ничего ставить не нужно —
ни Python, ни pip, ни пакеты.

![схема](docs/scheme.txt)

## Быстрый старт (из исходников)

```bash
python launcher/cli.py           # или: python -m launcher
python -m launcher --list        # что умеет запускать
python -m launcher --self-test   # 42 проверки без экрана и сети
```

Требуется только Python 3.10+ с tkinter (входит в установщик Python для Windows).

## Сборка exe

```bash
pip install -r launcher/requirements.txt
python launcher/build_exe.py
```

Готовый файл — `dist/CRM Agents.exe`. Сборка делается на той ОС, для которой нужен
exe (PyInstaller не кросс-компилирует). Полезные флаги:

| Флаг | Что делает |
| --- | --- |
| `--no-install` | не ставить зависимости (они уже есть) |
| `--onedir` | собрать папкой: быстрее стартует, но файлов много |
| `--wheels` | скачать колёса в `launcher/wheels/` — для офлайн-доустановки |

Что попадает в сборку:

* `launcher/*.py` — интерфейс и запуск;
* `agent/desktop_operator.py`, `agent/agent.py`, `agent/fileforge.py` → внутрь exe
  в папку `agents/`;
* пакеты из `launcher/requirements.txt` — замораживаются PyInstaller'ом;
* `launcher/wheels/`, если папка есть, — запасной офлайн-источник пакетов.

## Как приложение запускает агентов без Python на машине

В exe нет отдельного интерпретатора, поэтому приложение запускает **самого себя**
в режиме агента:

```
CRM Agents.exe --run-agent agents/desktop_operator.py --watch --token … --model …
```

`--run-agent` выполняет встроенный скрипт в текущем процессе (`runpy`) — так
работают встроенные агенты. Для «своего агента» нужен Python на машине: путь к
интерпретатору берётся из `sys.executable`, поэтому в exe это работает только для
встроенных скриптов (приложение честно предупредит об этом).

## Агенты

| Агент | Что делает | Нужно |
| --- | --- | --- |
| **Оператор рабочего стола** (`desktop_operator.py`) | смотрит на экран, кликает, печатает, собирает файлы; режимы «слушать очередь CRM», «одно задание», «разовое задание» | модель с vision, экран, токен CRM |
| **Агент с инструментами** (`agent.py`) | чат-агент для страницы `/ai`: файлы, сайты, видео; поднимает локальный сервер | модель |
| **Свой агент** | любой ваш `.py` с аргументами | Python на машине |

Поля агентов хранятся отдельно друг от друга: переключение не затирает введённое.

## Настройки и где они лежат

| Что | Windows | Linux/macOS |
| --- | --- | --- |
| Настройки | `%APPDATA%\CRM Agents\launcher.json` | `~/.config/crm-agents/launcher.json` |
| Рабочая папка агентов | `%APPDATA%\CRM Agents\workspace` | `~/.config/crm-agents/workspace` |
| Свой каталог агентов | `agents.json` рядом с настройками | там же |

`CRM_LAUNCHER_CONFIG=/path/to/settings.json` переносит всё в указанное место —
удобно для «портативной» сборки на флешке.

Ключ API на диск не пишется, пока не отмечена галочка «Сохранять ключ API».
В журнале и в строке запуска секреты заменяются на `•••`.

## Свои агенты

1. Положите скрипт рядом с приложением (или укажите его путь в поле «Python-файл»).
2. Либо опишите агента в `agents.json` рядом с настройками:

```json
{
  "agents": [
    {
      "id": "my-bot",
      "title": "Мой бот",
      "subtitle": "делает что-то полезное",
      "description": "Описание для карточки",
      "script": "my_agent.py",
      "requires": ["model"],
      "fields": [
        {"key": "target", "label": "Куда смотреть", "kind": "text", "default": "C:\\docs"},
        {"key": "loud", "label": "Подробный лог", "kind": "bool", "default": true}
      ]
    }
  ]
}
```

Скрипт получит аргументы `--target … --loud` и переменные `AGENT_BASE_URL`,
`AGENT_MODEL`, `AGENT_API_KEY`. Файл `my_agent.py` кладётся в папку `agents/`
внутри сборки либо указывается абсолютным путём в `script`.

## Зависимости и офлайн

- В собранном exe зависимости уже внутри: проверка «Проверить окружение» покажет
  «есть» для Pillow / pyautogui / pyperclip.
- Если exe собрали без них, приложение предложит доставить пакеты из
  `wheels/` рядом с exe (`pip install --no-index --find-links`), без интернета.
  Колёса готовятся флагом `python launcher/build_exe.py --wheels`.
- Для запуска из исходников: `pip install -r launcher/requirements.txt`.

## Горячие клавиши

| Клавиши | Действие |
| --- | --- |
| `Ctrl+Enter` | запустить выбранного агента |
| `Ctrl+.` | остановить |

## Что проверяет self-test

`python -m launcher --self-test` — 42 проверки:

* каталог агентов и провайдеров;
* сборка аргументов оператора (режимы, параметры генерации, флаги проверки и
  антизацикливания) и переменных `agent.py`;
* разбор аргументов своего агента с кавычками;
* секреты не попадают в описание команды и в файл настроек без разрешения;
* сохранение/загрузка настроек;
* проверка зависимостей и поиск скриптов в сборке;
* запуск процесса и чтение вывода, вырезание ANSI;
* `--run-agent` выполняет скрипт;
* `launcher.spec` исполняется с заглушками PyInstaller: точка входа, агенты в
  `datas`, скрытые импорты, оконный режим exe;
* интерфейс на заглушке tkinter: форма, смена агента, подстановка провайдера,
  запуск агента и запись в журнал, сохранение настроек при выходе.
