# Оператор рабочего стола: как запустить

Бот, который видит ваш экран и делает то, что вы написали: открывает программы,
кликает, печатает, лазает по сайтам и собирает файлы. Задания ставятся в CRM
(вкладка **«Оператор»** в блоке ИИ), а бот выполняется на вашем компьютере —
только там есть экран и мышь.

```
CRM (/ai → Оператор)  ⇄  desktop_operator.py (ваш ПК)  ⇄  модель (локальная или API)
        очередь заданий, шаги, файлы                скриншот → действие
```

## 1. Что нужно

* Python **3.9+**;
* запущенная CRM (`npm run dev` или `npm start`);
* модель: локальный сервер (vLLM, llama.cpp, LM Studio, Ollama) или облачный
  API по ключу — бот работает и так, и так.

## 2. Установка

Зависимости нужны только оператору (агент в чате работает без них):

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r agent/requirements.txt
```

Что ставится и зачем:

| Пакет | Зачем |
| --- | --- |
| `pyautogui` | скриншоты, клики, клавиатура |
| `Pillow` | сжатие скриншота перед отправкой модели |
| `pyperclip` | ввод кириллицы (pyautogui пишет только латиницу) |

Linux (X11), если не хватает системных пакетов:

```bash
sudo apt install python3-tk scrot
```

macOS: разрешите терминалу «Запись экрана» и «Универсальный доступ»
(Системные настройки → Конфиденциальность и безопасность).

## 3. Токен бота

1. Войдите в CRM как **главный администратор**.
2. Откройте **`/ai` → вкладка «Оператор»**.
3. Нажмите **«Создать токен»** и скопируйте его — показывается он один раз.
   Повторное нажатие «Обновить токен» отзывает старый.
4. Вставьте токен в поле **«Проверка токена»** и нажмите **«Проверить связь»** —
   CRM ответит, что токен принят, и покажет очередь. Если токена под рукой нет,
   создайте новый: старый уже не восстановить.

Токен длинный (`crmop_` + 48 hex-символов) и копируется целиком. Маска в бейдже
(«…abcdef») — только подсказка, командой она не работает; плейсхолдер
`<токен из шага 1>` CRM тоже не примет.

## 4. Запуск

Из папки проекта (там, где `agent/`):

```bash
# локальная модель (vLLM/LM Studio на 127.0.0.1:8000)
python3 agent/desktop_operator.py --watch --token ВАШ_ТОКЕН --provider local

# облачный API: ключ из переменной окружения
export OPENROUTER_API_KEY=sk-...           # Windows: set OPENROUTER_API_KEY=sk-...
python3 agent/desktop_operator.py --watch --token ВАШ_ТОКЕН \
  --provider openrouter --model qwen/qwen2.5-vl-72b-instruct

# OpenAI
python3 agent/desktop_operator.py --watch --token ВАШ_ТОКЕН \
  --provider openai --model gpt-4o-mini --api-key sk-...
```

CRM по умолчанию ищется на `http://localhost:3000`; если она на другом адресе —
`--server http://192.168.1.10:3000`.

Ключ облачного провайдера удобнее не писать в терминале, а вставить в поле
**«Ключ API»** в «Подключении»: он подставится в команду флагом `--api-key`
(или строкой `export DEEPSEEK_API_KEY=…`, если переключить режим). Ключ остаётся
в вашем браузере и в команде — в CRM он не уходит и в базе не хранится.
Для локальной модели ключ обычно не нужен.

Перед первым запуском проверьте связь — это не требует ни экрана, ни модели:

```bash
python3 agent/desktop_operator.py --check --server http://localhost:3000 --token crmop_…
```

```
[11:05:00] CRM: http://localhost:3000
[11:05:00] Токен: crmop_…1f9c
[11:05:00] Токен принят: Иван Петров <admin@crm.ru>
[11:05:00] Задания: в очереди 1, в работе 0, готово 3
```

Если токен не подходит, увидете «CRM отклонила токен агента» с маской токена и
адресом сервера — значит, дело в токене, а не в модели. Ошибка 401 от модели
теперь так и называется: «Модель отклонила ключ API».

`--check` проверяет не только CRM: при облачном провайдере (или явном `--model`)
бот отправляет модели минимальный запрос на один токен и печатает
«Модель … ответила: ключ принят» либо точную причину отказа. Для локальной
модели без `--model` проверка ключа пропускается.

В консоли появится:

```
[11:05:02] Модель: gpt-4o-mini @ https://api.openai.com/v1
[11:05:02] Режим: ИСПОЛНЕНИЕ
[11:05:02] Аварийная остановка: уведите мышь в левый верхний угол экрана.
[11:05:03] Сервер CRM: http://localhost:3000
[11:05:06] Жду задание в очереди…
```

## 5. Первое задание

В CRM: **`/ai` → «Оператор» → «Пульт»**. Там два чата:

1. **Планировщик** — вы описываете задачу словами («открой Telegram и напиши
   Ивану, что я задержусь»), модель задаёт уточняющие вопросы и пишет точный
   план: что открыть, куда кликнуть, что набрать, по какому признаку считать
   задачу выполненной. К плану можно приложить файлы — их текст тоже уходит в
   модель.
2. **Выполнение** — сюда план попадает кнопкой **«Перенести в выполнение»**
   (или своей формулировкой). Это уже задание бота: он кликает по экрану и
   присылает шаги.

Ничего не выполняется само: пока вы не нажмёте «Перенести в выполнение» или
«В очередь», бот ничего не трогает.

Задание уходит в очередь, бот забирает его в течение пары секунд. Лимит шагов —
до **500** (поле «Лимит шагов» в чате с действиями). На вкладке видно каждый шаг:
мысль модели, выполненное действие, проверка результата (`✅` / `⚠️`), ошибки и
готовые файлы — они скачиваются прямо из браузера.

Проверить без CRM и без ожидания очереди:

```bash
python3 agent/desktop_operator.py --task "открой сайт youtube.com и включи видео про космос"
```

## 6. Файлы

### Файлы от пользователя

К заданию можно приложить до **5 файлов по 10 МБ** — и в планировщике, и в чате
с действиями. Текст распознаётся в браузере (`src/lib/fileExtract.ts`), поэтому
боту не нужны офисные библиотеки:

| Формат | Что видит модель |
| --- | --- |
| `txt`, `md`, `csv`, `json`, `log`, код | содержимое как есть |
| `docx`, `xlsx`, `pptx` | текст из XML внутри архива |
| `pdf` | пометка «содержимое не извлекается» (текст PDF не парсится) |
| картинки | передаются модели как изображение (до 3 штук): бот видит снимок |

Бот скачивает вложения задания сам: `GET /api/agent/bot/attachment/<id>` с
токеном агента, и вставляет текст в первый запрос к модели. В ленте шагов
появляется строка «Прочитал вложения задания».

### Файлы от бота

Бот собирает файлы сам (модуль `fileforge.py`) и сразу отправляет их в CRM:

| Тип | Как формируется содержимое |
| --- | --- |
| `docx` | markdown-подобный текст: `# Заголовок`, `- пункт`, обычные строки |
| `xlsx` | строки CSV через `;` (первая строка — заголовки) или JSON-массив |
| `csv`, `tsv` | как есть |
| `md`, `txt`, `json`, `html`, `svg` | как есть (HTML/SVG при необходимости оборачиваются) |
| `zip` | JSON: `{"files": [{"name": "a.txt", "content": "…"}]}` |

Копии сохраняются локально в `agent/files/` (папка в `.gitignore`). В CRM файл
хранится в базе и отдаётся по `/api/agent/file/<id>` — ссылка «скачать» есть в
карточке шага.

## 7. Полезные флаги

| Флаг | Смысл |
| --- | --- |
| `--watch` | ждать задания из очереди CRM |
| `--once` | взять одно задание и выйти |
| `--task "…"` | выполнить задание сразу, без CRM |
| `--dry-run` | только планировать, ничего не нажимать |
| `--yes` | не спрашивать подтверждение опасных действий |
| `--max-steps 200` | жёсткий предел шагов (0 — лимит из задания, максимум 500) |
| `--delay 1.5` | пауза между шагами, сек |
| `--poll 5` | как часто опрашивать очередь, сек |
| `--max-width 1280` | ширина скриншота (меньше — дешевле запросы) |
| `--text-only` | не отправлять скриншоты (модель без vision) |
| `--check` | проверить связь с CRM и токен (без экрана и модели) |
| `--offset-x` / `--offset-y` | смещение координат, если окно на втором мониторе |
| `--vision` | модель точно понимает картинки: проверку зрения пропустить |
| `--no-cursor-marker` | не рисовать красный крестик в точке курсора |
| `--no-vision-check` | не проверять, понимает ли модель картинки |
| `--temperature`, `--top-p`, `--max-tokens`, `--seed` | параметры генерации модели |
| `--reasoning default\|off\|low\|medium\|high\|budget` | режим раздумий (`reasoning_effort`) |
| `--thinking-budget 2048` | бюджет раздумий в токенах для `--reasoning budget` |
| `--no-thinking-flag` | не дублировать режим в `chat_template_kwargs.enable_thinking` |
| `--no-verify-actions` | не проверять экран после каждого действия |
| `--self-test` | проверки координат, вложений и генерации без экрана |

## 8. Настройки модели и проверка каждого действия

На вкладке «Оператор» есть блок **«Раздумья и генерация»** — те же ручки, что в
«Чате с моделью»: режим раздумий, бюджет, `temperature`, `top_p`, `max_tokens`,
`seed`. Они действуют в двух местах:

* **планировщик** (`/api/agent/plan`) получает их вместе с вопросом;
* **бот** — через флаги команды запуска (`--temperature`, `--reasoning` и т. д.).
  Меняете настройки — скопируйте команду в «Подключении» заново.

Ещё один переключатель — **«Анализировать экран после каждого действия»**
(включён по умолчанию). После клика, ввода, прокрутки или перетаскивания бот:

1. ждёт 0,35–1,5 с, чтобы интерфейс успел обновиться;
2. снимает свежий скриншот (с крестиком курсора);
3. спрашивает модель: «получилось ли?» — и получает
   `{"ok": true|false, "note": "что видно"}`;
4. отправляет в CRM событие `result`: `✅ окно открылось` или
   `⚠️ результата не видно`, и добавляет вердикт в историю шагов — следующее
   решение модель принимает уже с этой поправкой.

Проверка добавляет один запрос к модели на действие; если это дорого или модель
медленная, выключите её в интерфейсе (флаг `--no-verify-actions`).

## 9. Точность кликов

Бот работает по скриншоту: модель видит кадр и отвечает координатами **в пикселях
кадра**. Бот сам масштабирует их на экран (кадр 1600×900 → экран 1920×1080,
Retina, DPI) и поддерживает ответы долями кадра (`0.5, 0.5` = центр).

Чаще всего «промахи» — не баг пересчёта, а модель без зрения: она придумывает
координаты, и бот аккуратно кликает в пустоту. Зрение зависит не от провайдера,
а от **модели**:

| Провайдер | Vision-модель | Без зрения |
| --- | --- | --- |
| DeepSeek | `deepseek-flash` | `deepseek-chat`, `deepseek-reasoner`, `deepseek-v4-pro` |
| OpenAI | `gpt-4o-mini`, `gpt-4o` | `gpt-3.5*` |
| OpenRouter | `qwen/qwen2.5-vl-72b-instruct` и другие `*-vl` | текстовые модели |
| Groq | `meta-llama/llama-4-scout-17b-16e-instruct` | `llama-3.3*` |
| Together | `Qwen/Qwen2.5-VL-72B-Instruct-Turbo` | текстовые модели |
| Mistral | `pixtral-12b-2409` | `mistral-large`, `mixtral` |
| Локально | `Qwen/Qwen3-VL-8B-Instruct` | текстовые сборки |

Проверка устроена так:

* при старте бот сам проверяет зрение — просит модель прочитать число с тестовой
  плашки. В консоли будет «Зрение модели: проверено — картинки читает» либо
  предупреждение с подсказкой про `deepseek-flash`;
* заведомо текстовые id (`deepseek-chat`, `deepseek-reasoner`, `deepseek-v4-pro`,
  `gpt-3.5`, `llama-3.3`, `mixtral`) отмечаются ещё до первого задания;
* новая vision-модель ничего не блокирует: если проверка ошибается, запустите с
  `--vision` — проверка и предупреждения отключатся. Также есть
  `--no-vision-check` — просто не проверять, оставив все шаги как есть;
* в «Подключении» для DeepSeek по умолчанию подставляется `deepseek-flash`;
  предупреждение появляется только если в поле модели явно указана текстовая
  модель.

На каждом скриншоте текущее положение курсора отмечено **красным крестиком** —
модель видит, где он, и не кликает «наугад» после промаха. Если курсор мешает,
запустите с `--no-cursor-marker`.

Перед каждым кликом бот не просто наводит курсор, а **проверяет, что он встал
куда надо**:

1. `moveTo(x, y)` и короткая пауза — успевают сработать hover-меню;
2. `pyautogui.position()` сверяется с целью (допуск 3 px); при расхождении —
   одна повторная попытка;
3. если курсор снова не там или точка вообще вне экрана, клик **отменяется**, а
   в ленту уходит ошибка «курсор встал в (…, …) вместо (…, …) — клик отменён».
   Модель видит её и пробует снова — вместо того чтобы открыть чужое приложение.

Так же проверяются `move`, ввод с координатами, прокрутка и перетаскивание.

Если окно на втором мониторе, задайте смещение: `--offset-x 1920`
(pyautogui снимает только основной экран).

## 10. Ввод текста в чат

`type` умеет кликать в поле перед вводом — так текст не уходит в случайное окно:

```json
{"type":"type","text":"Привет, буду через 10 минут","x":640,"y":940,"clear":true}
```

* `x`, `y` — координаты поля ввода в пикселях кадра; без них текст пойдёт в то
  окно, которое сейчас активно (именно так он иногда попадал в документ);
* `clear: true` — сначала очистить поле (Ctrl/Cmd+A, Delete);
* `paste` — то же самое, но длинный текст и кириллицу бот вставляет через буфер
  обмена: `pyautogui.write` их теряет;
* для отправки сообщения модель вызывает `{"type":"key","key":"enter"}`.

В системном промпте прямо сказано: чтобы написать в чате — кликнуть в поле ввода
внизу окна, набрать текст, проверить по следующему скриншоту, что он появился
именно в поле ввода, и только потом отправить. Если текст ушёл не туда —
модель должна вернуться и кликнуть точнее, а не продолжать.

## 11. Остановка задания

Кнопка «Остановить» на «Пульте» переводит задание в `cancelled`. Бот проверяет
статус перед каждым шагом (`GET /api/agent/bot/<id>`) и сразу выходит:

```
[12:30:41] Задание отменено в CRM — останавливаюсь, шаги больше не шлю.
```

Сообщений «не смог отправить шаг в CRM: HTTP 409» больше нет: ответ 409 с
`cancelled` бот распознаёт как остановку, а не как ошибку, и ничего не досылает.
Статус отменённого задания нельзя перезаписать на `failed` — сервер тоже это
проверяет.

## 12. Безопасность

* **Аварийная остановка**: резко уведите курсор в левый верхний угол — pyautogui
  прервёт выполнение.
* **Опасные действия** (удаление, переводы, покупки, пароли) бот спрашивает в
  консоли; `--yes` отключает вопрос, `--dry-run` не выполняет ничего.
* **Ключ API остаётся на вашем компьютере**: в CRM он не передаётся и в базу не
  пишется. CRM хранит только текст задания, шаги и файлы.
* **Скриншоты не сохраняются** ни в CRM, ни на диске: они живут в памяти до
  отправки модели.
* Токен бота даёт доступ только к очереди заданий своего владельца; отозвать —
  кнопкой «Обновить токен».

## 13. Если что-то не так

| Симптом | Что делать |
| --- | --- |
| «Не удалось загрузить pyautogui» | `pip install -r agent/requirements.txt`, на Linux — X11 и `python3-tk`, `scrot` |
| «CRM отклонила токен агента» | токен отозван, скопирован не целиком или создан в другом аккаунте / другой CRM: сверьте адрес `--server`, проверьте `--check`, затем создайте токен заново во вкладке «Оператор» → «Подключение» |
| «В команде остался плейсхолдер» | в команду не подставлен токен — скопируйте его из шага 1 или вставьте сохранённый в «Проверку токена» |
| «Задание отменено в CRM — останавливаюсь» | это штатная реакция на «Остановить» в интерфейсе; запустите бота снова, если нужно |
| «Жду задание в очереди…» и ничего | проверьте `--server` (адрес CRM) и что задание в статусе «в очереди» |
| Бот «промахивается» по кнопкам | проверьте зрение модели: у DeepSeek нужен `deepseek-flash`, `deepseek-chat` картинок не принимает; если модель точно vision, запустите с `--vision` |
| Текст уходит в блокнот/документ вместо чата | модель не кликнула в поле ввода: попросите в задании «напиши в чате…», бот теперь кликает по `x,y` из action `type`; проверьте, что окно чата на экране, а не свёрнуто |
| Окно на втором мониторе, клики мимо | `--offset-x 1920` (ширина основного экрана) и `--offset-y 0`; скриншот снимается только с основного монитора |
| «Модель отклонила ключ API (401)» | ключ не задан, неверный или от другого провайдера: вставьте его в поле «Ключ API» в «Подключении» (флаг `--api-key`), либо задайте переменную провайдера (`DEEPSEEK_API_KEY`, `OPENAI_API_KEY`, …); это не токен CRM |
| Модель отвечает без JSON | возьмите модель посильнее (`gpt-4o-mini`, `qwen2.5-vl-72b`) или уменьшите `--max-width` |
| Клики «мимо» | обновите масштаб: бот сам пересчитывает DPI/Retina, проверьте `--self-test`; на Windows DPI-awareness включается автоматически |
| Файл не пришёл в чат | смотрите консоль: если CRM недоступна, файл всё равно сохранён в `agent/files/` |
